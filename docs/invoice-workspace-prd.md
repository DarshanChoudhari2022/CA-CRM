# PSB Invoice workspace

**Audience:** PSB administrators. **Entry:** Switch workspace → Invoice. The workspace uses PSB identity and the supplied BillSetu screenshots as the layout reference.

## Outcome

An administrator can prepare a bill, issue it, collect payment, and reconcile the client account in one workspace. CA CRM and Invoice use the same client, invoice, and invoice-payment records so existing PDFs, reminders and reports continue to work.

## Requirements

| Sidebar | User workflow and acceptance criteria |
| --- | --- |
| Dashboard | Select a reporting period. Show invoiced, collected, outstanding and average invoice value. Display billed and collected trends, collection progress and shortcuts to issue a note, add a client, create a quotation and raise an invoice. Drafts and cancelled invoices are excluded from revenue. |
| Invoice Ledger | Filter by status, client, invoice number or amount, and date. Page results on the server. Show invoice date, number, client, due date, total, balance and payment status. Open an invoice, download its PDF, record a payment, cancel where eligible and export matching records. |
| Raise Invoice | Select a client and services, enter quantities and rates, apply discounts, set dates, and preview the document alongside the editor. Save a draft or issue the invoice. Existing issued invoices keep their number, amount and document snapshot. |
| Credit & Debit Notes | Prepare notes with a client, reference invoice, reason and line items. Issuing a note must post the correct balance adjustment and retain an audit trail. |
| Quotations | Create and preview a quotation, track its status and validity, and convert an accepted quotation to an invoice once. |
| Proforma Invoices | Prepare a non-posting proforma and convert it to an invoice explicitly. |
| Recurring Invoices | Configure cadence, next run and pause state. Each schedule and billing period must create at most one draft. Issuing and delivery require explicit policy. |
| Smart Drafts | Map authenticated filing events to billable services and create one reviewable draft per event. KDK event intake depends on an authorized provider integration and documented event contracts. |
| Receipts | Record payments against invoices and show partial or full settlement. Track advances separately until allocated, with no double counting. |
| Client Directory | Use the shared client records, capture billing details, and open a dated client ledger. Any KDK sync requires a supported connection and a deduplication rule. |
| Service Catalog | Search and maintain service names, SAC codes, tax rates and standard fees. The builder can copy these values into an editable line item. |
| Practice Settings | Configure firm identity, bank/UPI, branding, document numbering, credit terms and sharing preferences. Issued documents retain the settings used at issue time. |
| What's New | Show which workspace features are available and where to find them. |

## Design and delivery

- Match the reference hierarchy with a dark vertical navigation rail, violet selected states, compact filters, white tables and cards, and a two-pane editor on desktop. Stack the preview on smaller screens. Use existing PSB assets and omit the browser and meeting overlays.
- Guard each server-side entry point and tenant-scope database functions. Use existing invoice numbering, decimal calculations, audit records and payment locks where applicable.
- Run aggregates and pagination in PostgreSQL. Keep document editing client-side and query only the data needed by each page. Export within a bounded range.
- Verify role denial, tenant isolation, report totals, PDF and draft transitions, payment reconciliation, pagination and export. Validate the invoice tax and numbering policy with the firm before statutory use.
- Verify delivery channels separately with approved credentials, recipient permissions and a demo destination before enabling automatic sends.

Reference: [KDK BillSetu user guide](https://support.kdksoftware.com/portal/en/kb/articles/billsetu-user-guide).

## Implementation and rollout

The new workspace uses the shared CRM ledger for issued invoices and payments. It adds a server-paginated CSV export, live document previews, quotation acceptance and one-time conversion, proforma conversion, advance allocation, and client balance summaries. Invoice sharing opens a message draft using the configured templates. Recurring drafts are generated by an administrator running due schedules. Smart Drafts accepts filed CA CRM records and deduplicates by filing.

The reference shows workflows that require further integration. Notes can be drafted and previewed, while posting their accounting effects is pending. Client opening balances, expanded tax identifiers, GST/RCM calculations, statutory exports, full payment metadata on invoice receipts, automated recurring runs, KDK sync and filing events, and provider-driven delivery are pending. Settings for firm details, banking, branding and numbering can be saved. Existing PSB PDF branding and numbering remain the source for issued documents.

Apply the Invoice migrations in timestamp order to a test database before running acceptance. The rollback check is `node --env-file=.env.local scripts/test-invoice-workspace-db.mjs --preview` against the baseline schema. After migration, run the same script without `--preview`. For visual acceptance, verify dashboard, ledger, editor and settings at desktop and mobile sizes as an administrator. Check an employee cannot open those routes or invoke the billing RPCs.
